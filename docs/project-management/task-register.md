This register mirrors the Linear team **PHA2** (link will be added when the instance is confirmed) so that the task history is readable from the repository without access to the tracker. It lists every task with its responsible member, expected outcome, acceptance criteria, deadline, status and branch. Statuses are given **as of 2026-10-20**. The register is updated when a pull request is merged and before each weekly supervisor meeting; the Linear board remains the primary source and this file follows it.

## 1. Conventions

| Field | Convention |
|---|---|
| ID | `PHA2-<n>`, assigned by Linear in order of creation; the same ID is used in the branch name, commit messages (`type(scope): subject [PHA2-<n>]`) and the pull request title |
| Responsible | The assignee of the task; "with" names members who co-authored parts of the result and reviewed it |
| Expected outcome | The deliverable in the repository (files, features, results) |
| Acceptance criteria | What the reviewer checks before the pull request is merged and the task is closed |
| Deadline | The date agreed in Linear (ISO format) |
| Status | **Planned**: created, not started or in progress without an open pull request; **In review**: pull request open; **Done**: merged into `main` and acceptance criteria confirmed by the reviewer |
| Branch | `PHA2-<n>-<slug>` as described in `CONTRIBUTING.md` section 3; exceptions are noted; for planned tasks the intended name is given and the branch is created when work starts |

## 4. Maintenance

- The responsible member moves the task in Linear and updates this file in the same pull request that closes the task, or in the next pull request that touches `docs/project-management/`.
- Before each weekly supervisor meeting Evelina checks the register against the merged branches on `main` and the open pull requests, and updates section 2.
- New tasks are added when they are created in Linear with at least the title, the responsible member and the deadline; the expected outcome and acceptance criteria are completed before work starts.
- Deadlines that move are changed in Linear first; the reason is recorded in `docs/supervision/feedback-log.md` when the change was discussed with the supervisor.
